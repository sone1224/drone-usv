# 수상드론 공통 플랫폼 제품요구사항문서(PRD)

Oct 20, 2026 · @손종락

## 1. 개요와 범위

이 문서는 상용부품(COTS)으로 쉽게 조립하고 값싸고 빠르게 대량 생산하는
수상드론 공통 플랫폼의 제품 요구사항을 시스템·서브시스템·엘리먼트
수준으로 정의합니다. 하나의 플랫폼에서 민간·공공 3종과 군용 1종을 파생하며,
모든 모델에서 중국산 부품을 배제합니다.

| 항목      | 내용                                                                                                                         |
|-----------|------------------------------------------------------------------------------------------------------------------------------|
| 제품군    | A 인명구조형(3m급), B 해양관측형(6m급), C 군용 저가 소모형 플랫폼(6~7m급 이하), D 국가중요시설 해역 감시·정찰형(4~5m급(안))      |
| 제품 목표 | 공통 모듈 4개(선체·추진, 전원, 전장 함체, 통신·센서)로 네 모델을 조립해 부품 공용화와 양산 단가 인하                         |
| 출시 기준 | 2027년 초 프로토타입(모델 A 기준)                                                                                            |
| 포함 범위 | 선체·추진·전원·전장 함체·통신·항법·센서·상태감시·지상통제소, 임무 베이의 기계·전기·데이터 인터페이스                         |
| 제외 범위 | 군용 임무장비 내부(탄두·신관·유도·표적화). 정부가 지정한 체계업체가 설계·통합하며, 본 문서는 임무 베이 인터페이스까지만 정의. 모델 D는 감시·정찰과 비살상 경고(방송·탐조등)까지만 다루며 무장·차단 장비는 포함하지 않음 |
| 문서 상태 | 초기본. 수치는 모두 초기 목표안이며 프로토타입 시험과 수요기관 협의로 확정                                                   |

## 2. 수요기관과 운용 시나리오

수요기관은 네 묶음이며, 모두 ‘원격 운용 + 일부 자율 + 통신 두절 시 안전
복귀’를 공통으로 요구합니다.

| 모델               | 수요기관                            | 대표 시나리오                                                                                                | 운용 환경                          |
|--------------------|-------------------------------------|--------------------------------------------------------------------------------------------------------------|------------------------------------|
| A 인명구조형       | 해양경찰청, 소방청(수난구조대)      | 차량으로 현장 이동 → 2인 이하로 수동 진수 → 열화상으로 요구조자 탐색 → 구조부이 전달 → 복귀                  | 급류·저시계·야간, 연안·하천·저수지 |
| B 해양관측형       | 해양수산부, 지자체, 해양 연구기관   | 지정 구역을 경로점으로 자율 순항 → 기상·수질·영상 자료 수집 → 유출유 등 이상 징후 시 관제소 경보             | 연안·어장, 장시간 운용             |
| C 군용 저가 소모형 | 국방부·방위사업청, 국과연, 체계업체 | 수요군 작전요구성능(ROC)에 따름. 본 문서는 플랫폼의 대량 생산·저장·전개 용이성과 임무 베이 인터페이스만 정의 | 연안·외해, 전자전 환경             |
| D 국가중요시설 감시·정찰형 | 원자력발전소 운영사(한국수력원자력), 항만공사·해양수산부, 해양경찰청, 지역 군 부대(통합방위 협조) | 계류 도크에서 교대 출동 → 경계구역 경로 반복 순찰 → 레이더·주야간 EO/IR·AIS 대조로 미식별 선박 탐지 → 경계구역 접근·침입 시 자동 경보·추적·영상 전송 → 보안관제센터 판단에 따라 경고 방송·탐조등 → 해경·경비 인력 출동 연계 | 원전 취·배수구 해역, 국가주요항만 입구·정박지, 24시간·야간·악천후, 전파 혼잡·GNSS 교란 가능 |

## 3. 제품 요구사항

‘안’으로 표시한 값은 초기 목표이며 프로토타입 시험 후 확정합니다.

## 4. 시스템 구성

체계는 선체와 지상통제소로 나뉘고, 선체는 서브시스템 9개로 구성됩니다.
네 모델은 같은 9개 서브시스템을 쓰고 센서와 임무 베이의 내용물만
다릅니다.

협력으로 확보합니다. 나머지는 비중국산 상용부품을 조립합니다.

## 5. 서브시스템·엘리먼트 설계

제품 차별화가 일어나는 전원·전장 함체·통신·항법 4개 서브시스템을
엘리먼트 수준까지 나눌니다. 선체·추진·센서·임무 베이는 상용부품을
선택·조립하므로 부품 선정 단계에서 상세화합니다.

## 6. 통신 규격 검토와 권고안

민간 모델은 공개·상용 규격(MAVLink 2, NMEA 2000, CAN, Ethernet)으로
빠르게 만들고, 군용 모델은 같은 내부 버스 위에 군 상호운용성
게이트웨이를 얹는 구조를 권고합니다. 하드웨어는 같고 소프트웨어 계층만
다르게 해 양산 단가를 지킵니다.

| 구분                  | 규격                                            | 용도                                     | 검토 의견                                                                              | 권고                                |
|-----------------------|-------------------------------------------------|------------------------------------------|----------------------------------------------------------------------------------------|-------------------------------------|

## 7. 인터페이스 정의

내부는 Ethernet 백본과 CAN FD 제어 버스 두 개로 나누고, 운항 제어기가
둘을 잇습니다. 강조색 엘리먼트(상태감시 GW·BMS·PDU·열관리 제어기)가 당사
개발분입니다.

| IF ID | 연결                                 | 물리 계층                         | 프로토콜·규격                     | 비고                                                   |
|-------|--------------------------------------|-----------------------------------|-----------------------------------|--------------------------------------------------------|
| IF-01 | 지상통제소 ↔ 선체                    | LTE/5G                            | MAVLink 2 over IP, 링크 암호화    | 주 링크                                                |
| IF-02 | 지상통제소 ↔ 선체                    | 전용 무선·메시                    | MAVLink 2                         | 예비 링크, 주파수 허가 확인                            |
| IF-03 | 선체 ↔ 위성                          | 위성 단말                         | IP                                | B·C 예비, 사업자 미결                                  |
| IF-04 | 선체 ↔ 주변 선박                     | VHF                               | AIS(ITU-R M.1371)                 | C는 송신 제어                                          |
| IF-05 | 임무 컴퓨터 ↔ 센서·영상              | Ethernet                          | DDS, RTSP/RTP                     | 내부 고속                                              |
| IF-06 | 운항 제어기 ↔ 추진·BMS·PDU·열관리    | CAN FD                            | 당사 메시지 사전(부록으로 작성)   | 내부 제어                                              |
| IF-07 | 관측 센서·AIS·GNSS ↔ NMEA 게이트웨이 | NMEA 2000 / 0183                  | NMEA PGN·문장                     | B 관측 센서                                            |
| IF-08 | 임무 베이 ↔ 선체                     | 전원 + Ethernet + CAN + 기계 체결 | 표준 커넥터·체결구(안)            | C는 체계업체와 인터페이스만 합의, 내부는 정의하지 않음 |
| IF-09 | PDU → 전 엘리먼트                    | 전원 레일                         | 주전원 48V(안), 보조 24·12·5V(안) | 채널별 차단·계측                                       |
| IF-10 | 지상통제소 → 수요기관 상황실         | IP                                | 영상 스트림·상태 API              | 기관별 연동 방식 협의                                  |

인터페이스 검토 결과, 위험이 큰 곳은 IF-02(주파수 허가)와
IF-08(체계업체와의 합의)입니다. 두 항목은 프로토타입 설계 동결 전에
확정해야 합니다.
